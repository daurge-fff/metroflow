# Участие в разработке MetroFlow

Спасибо за интерес к проекту! Ниже — базовые правила разработки.

## Перед началом работы

1. Установите Rust (`rustup`) и инструменты командной строки Xcode (macOS).
2. Установите компоненты `rustfmt` и `clippy`:
   ```sh
   rustup component add rustfmt clippy
   ```
3. Соберите проект и прогоните проверки:
   ```sh
   cargo build
   cargo test
   cargo fmt --check
   cargo clippy --all-targets
   ```

## Требования к изменениям

- **Форматирование.** Весь код должен проходить `cargo fmt --check`.
- **Статический анализ.** Не допускаются предупреждения `cargo clippy`.
- **Тесты.** Новая логика должна сопровождаться тестами. Все существующие
  тесты должны продолжать проходить (`cargo test`).
- **Предупреждения компилятора.** Сборка должна проходить без предупреждений.
  Не подавляйте предупреждения `#[allow(...)]` без обоснованной причины.
- **Разделение слоёв.** Логика симуляции не должна зависеть от отрисовки или
  Macroquad. Используйте `geom::Vec2` и держите бизнес-логику в `network`,
  `simulation`, `save`.
- **Комментарии.** Добавляйте комментарии там, где решение неочевидно.
  Избегайте комментариев, повторяющих код.
- **Безопасность.** Не используйте `unsafe` без крайней необходимости.
- **Ресурсы.** Не добавляйте сторонние ассеты без проверки лицензии и
  обновления [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).

## Стиль кода

- Rust edition 2021, форматирование `rustfmt`.
- Имена: `snake_case` для функций/переменных, `CamelCase` для типов.
- Модульная структура: не складывайте всё в один файл.
- Ошибки обрабатывайте явно, не `unwrap`-ьте внешние данные.
- Избегайте аллокаций и создания строк в цикле отрисовки без необходимости.

## Структура модулей

- `network` — станции, линии, связи, демо-сеть.
- `simulation` — время, поезда, пассажиры.
- `save` — сериализация и загрузка.
- `camera` — координаты и управление видом.
- `render` — отрисовка.
- `ui` — интерфейс.
- `app` — сцены, ввод, основной цикл.
- `config` — палитра, шрифты, настройки.

## Процесс

1. Создайте отдельную ветку под изменение.
2. Делайте небольшие, логически цельные коммиты.
3. Перед отправкой на проверку убедитесь, что проходят `fmt`, `clippy`,
   `test` и `build --release`.
4. Опишите в изменениях, что и зачем сделано; для визуальных правок по
   возможности приложите описание поведения.
