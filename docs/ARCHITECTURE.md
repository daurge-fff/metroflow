# Архитектура MetroFlow

Документ описывает структуру проекта и принятые архитектурные решения.

## Общие принципы

1. **Симуляция не зависит от отрисовки.** Бизнес-логика работает с типом
   `geom::Vec2` и не обращается к Macroquad. Преобразование в экранные
   координаты выполняет только `camera`, а рисование — только `render`.
2. **Движение не зависит от частоты кадров.** Поезда двигаются по игровому
   времени (`dt` в секундах), а не по количеству кадров. При больших скоростях
   времени шаг разбивается на подшаги (`MAX_STEP = 0.05 с`).
3. **Тестируемость.** Логика построена так, чтобы её можно было проверить без
   окна: тесты покрывают сеть, камеру, часы, RNG, пассажиров, движение и
   сохранения.
4. **Явные ошибки.** Сеть и сохранения возвращают типизированные ошибки
   (`NetworkError`, `SaveError`) вместо паник.
5. **Без `unsafe`.** В коде проекта `unsafe` не используется.

## Модули

```
geom        2D-геометрия: Vec2, Rect. Не зависит от графики и сериализуется.
config      Палитра (Palette), стили линий, шрифты (Fonts), настройки (Settings).
network     Network: станции (Station) и линии (Line), связи, валидация, демо-сеть.
camera      Camera: target/zoom/viewport, мировые ↔ экранные координаты, зум.
simulation  SimClock, Train, PassengerModel, Rng, Simulation.
save        SaveData (версионированный JSON), атомарная запись, проверки.
render      RenderState, shapes, text, map — вся отрисовка.
ui          widgets (immediate-mode), layout, icons, hud, menu, editor, UiAction.
app         App: сцены, ввод, редактор, обработка UiAction, цикл кадра.
main        Настройка окна и запуск цикла.
```

## Поток данных

```
ввод → app → UiAction → обновление App/Simulation/Camera → render → кадр
```

Каждый кадр (`App::frame`):

1. вычисляются области экрана (`ui::layout::Layout`);
2. обновляется состояние отрисовки (`RenderState`);
3. в зависимости от сцены рисуется меню, настройки или симуляция;
4. обрабатываются горячие клавиши и полученные `UiAction`;
5. рисуется всплывающее уведомление;
6. `next_frame().await`.

В сцене симуляции порядок такой: обновление `Simulation` → обработка событий
(вспышки прибытий) → обновление `Camera` → отрисовка карты → отрисовка HUD →
обработка ввода карты (если курсор не над интерфейсом).

## Модель сети

- `Station` имеет `StationId`, имя, позицию, тип и список подключённых линий.
- `Line` имеет `LineId`, имя, цвет, стиль и **упорядоченный список станций**.
- Соединения определяются списками станций линий, а не пересечением на экране.
- `Network::validate` проверяет уникальность идентификаторов, корректность
  ссылок, минимальную длину маршрута, отсутствие соседних дубликатов и
  конечность координат.
- `Network::rebuild_connections` пересчитывает список линий у станций.

Демонстрационная сеть (`demo_network`) — 4 линии и 10 станций с центральным
узлом (3 линии) и несколькими пересадочными станциями.

## Модель симуляции

- `SimClock` хранит накопленное игровое время, множитель скорости и флаг паузы.
  Одна игровая секунда = одна игровая минута; отображаемое время начинается с
  06:00.
- `Train` ссылается на линию, позиционируется на сегменте (`segment` +
  `direction` + `progress`), хранит состояние (`Moving`/`Dwelling`),
  вместимость и число пассажиров. Позиция интерполируется вдоль сегмента, а не
  телепортируется.
- `PassengerModel` хранит ожидающих (со станцией назначения) и доставленных
  пассажиров по станциям. Появление выбирает исход и достижимую цель по весу
  типа станции. При стоянке пассажир садится только в поезд, который переходами
  к следующей станции уменьшает расстояние до цели (жадный выбор по числу
  сегментов); лишние выходят на пересадку, достигшие цели — учитываются как
  доставленные.
- `network::Routing` — матрица кратчайших расстояний между станциями (BFS по
  топологии линий и пересадок). Пересчитывается при изменении сети и не
  сериализуется.
- `Rng` (xorshift64) с сериализуемым состоянием обеспечивает воспроизводимость
  по сиду.

Инварианты: поезд не переполняется, движение по пустому маршруту невозможно,
деления на ноль нет (длины сегментов проверяются).

## Камера и координаты

Объекты хранятся в мировых координатах. `Camera` хранит `target` (мировую точку
в центре области карты), `zoom` и `viewport` (экранный прямоугольник карты):

```
world_to_screen(w) = (w - target) * zoom + viewport.center()
world_from_screen(s) = (s - viewport.center()) / zoom + target
```

Зум плавный и «привязан» к курсору: точка под курсором остаётся на месте.
Панорамирование — перетаскиванием, с порогом, отличающим клик от перетаскивания.

## Редактор карты

Редактор — это режим сцены симуляции (`App::edit_mode`). Состояние `EditorState`
хранит активный инструмент, выбранную линию и стопки снимков сети для отмены и
повтора. Любое изменяющее действие сначала кладёт копию `Network` в историю
(`UNDO_LIMIT = 50`), затем меняет сеть; после этого вызывается
`Simulation::reconcile`, который приводит поезда и пассажиров в согласованное
состояние. Типы станций пересчитываются из числа подключённых линий. Слой UI
(`ui::editor`) лишь рисует панели и возвращает `UiAction` — вся логика в `app`.

## Интерфейс

UI — простой immediate-mode. Каждый элемент рисуется каждый кадр и сообщает,
находится ли под ним курсор (`pointer_over_ui`) и какие действия вызваны
(`UiAction`). Приложение обрабатывает действия централизованно. Ввод по карте
игнорируется, если курсор над интерфейсом, поэтому клик по кнопке не выбирает
станцию под ней.

## Настройки, состав и аналитика

Настройки (`config::Settings`) хранят и параметры интерфейса, и параметры
симуляции: границы числа вагонов, вместимость вагона, авто-состав и уровень
пассажиропотока. `Simulation::apply_settings` применяет их живьём (пересчитывает
вместимости, интервал появления пассажиров). Состав поезда (`Train::adjust_cars`)
меняется по загрузке между заданными границами; вместимость — производная от
числа вагонов.

Экран аналитики (`ui::analytics`) читает `Simulation` и `History` каждый кадр —
работает в реальном времени, пока симуляция идёт. История — кольцевые буферы
(очереди, пассажиры в пути, среднее ожидание, пропускная способность); «доставлено»
хранится счётчиком, а не графиком.

## Сохранения

`SaveData` содержит версию формата, версию приложения, время и полные
`Network` + `Simulation`. Запись атомарная (временный файл + переименование).
Загрузка проверяет версию и целостность; при ошибке исходный файл не
перезаписывается. Каталог данных определяется через `directories::ProjectDirs`.

## Почему Macroquad

Macroquad — лёгкая кросс-платформенная библиотека с программным рисованием
примитивов, подходящая для векторной графики без тяжёлого движка. Она даёт
окно, ввод, текст, камеру и геометрию из коробки и не тянет лишних зависимостей.

## Известные компромиссы

- Отрисовка карты идёт в экранных координатах (ручное преобразование), а не
  через `Camera2D`: это упрощает совмещение карты и интерфейса в одном кадре.
- Ожидание и обслуженные пассажиры хранятся в `BTreeMap` для
  детерминированной сериализации.
